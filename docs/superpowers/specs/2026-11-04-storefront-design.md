# Customer storefront and API integration

User requested complete FE integration for product pages, cart, addresses, checkout and orders after confirming backend COD flow exists. The repository has only admin FE; add a customer storefront rather than fake API wiring into missing files. Use existing vanilla HTML/CSS/JS and available Ogani product assets, with a responsive green/cream grocery layout, accessible forms/status messages and real API data.

Pages: index catalog with filters/sort/pagination; product detail/gallery; login/register/forgot password as shopping prerequisites; cart read/add/absolute quantity update/delete; addresses list via checkout/addresses plus POST/PUT/DELETE/default PATCH; checkout preview/contact/address selection or save-new form/COD; own orders list/filter/sort/detail and allowed cancellation. No customer profile editing screen or admin-order FE is implied by this task. No online gateway/coupon/review/wishlist actions until supported.

Private pages verify current customer; tokens/session storage are isolated from admin. Price/stock/business rules remain BE-owned. Checkout persists a crypto UUID and exact request before sending, retries uncertain placement with same key/body, restores pending attempts before cart preview, and requests fresh confirmation on definitive conflicts. API/session races cannot restore a logged-out user. Pending state is user-scoped; expiration can return to login and resume, explicit logout clears local PII. Safe local return URLs prevent redirects off the app. GETs may be canceled; writes are serialized in the UI.

Backend serves /shop resources and local dev server supports VS Code; no frontend package dependencies. Existing backend contracts remain intact except static resource routing/build mapping. Validate API/checkout behavior in Node and actual browser flow with unique test user/product on test DB, including cancellation and staff-driven COD completion.
